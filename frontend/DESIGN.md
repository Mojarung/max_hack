# Дизайн мини-приложения «Домовой Кузя»

Этот документ задаёт рамки для любого изменения интерфейса. Если правило мешает
сделать экран понятнее, сначала меняйте правило здесь (с причиной), потом код.

## Для кого

- **Житель панельного дома**, часто 50+ лет, открывает приложение из домового чата MAX
  на телефоне, одной рукой, иногда на улице и в стрессе (течёт крыша, тревога).
- Не читает инструкции. Экран должен сам подсказывать следующий шаг.
- Приходит с одной задачей: сообщить о проблеме, поддержать соседа, записаться на событие,
  найти укрытие. Всё остальное вторично.

## Принципы (по убыванию важности)

1. **Одно главное действие на экран.** Одна заливная кнопка `color="primary"` `variant="flat"`.
   Остальные действия тональные (`tonal`), текстовые (`text`) или в меню.
2. **Состояние видно без чтения.** Статус = иконка + подпись (не только цвет). Прогресс = полоса + «4 из 6».
   Срок = таймер с понятной формулировкой («осталось 18 ч», «просрочено на 20 ч»).
3. **Каждое состояние говорит, что делать дальше.** Пустой список, ошибка, просрочка, успех:
   текст «что произошло» + кнопка следующего шага. Тупиков нет.
4. **Язык жителя, а не системы.** «Меня это тоже касается», а не «Проголосовать».
   «Кто отвечает», а не «Ответственная организация». Кузя говорит от первого лица, коротко и по-доброму.
5. **Крупно и спокойно.** Тач-зоны от 44px (основные кнопки от 52px), текст от 14px (основной 16px),
   расстояние между нажимаемыми элементами от 8px.
6. **Кузя - индикатор, а не декор.** Настроение маскота отражает реальное состояние дома.
   Не ставить маскота туда, где он отнимает место у действия.

## Палитра

Спокойная нейтральная основа, синий - фирменный цвет и главное действие, смысловые цвета - только
для состояний. Значения и проверенный контраст - в `src/plugins/vuetify.ts` (объекты `L` и `D`).

> История: до сентября 2026 палитра была из 9 оттенков голубого без красного и зелёного. По пункту
> заказчика «Изменить цвета» и по итогам проверки (статусы «Решено» и «Собираем голоса» выглядели
> одинаково, голубой фон утомлял, в тёмной теме тревога становилась самым светлым цветом) палитру
> заменили.

| Токен | Смысл | Где |
|---|---|---|
| `primary` (синий) | главное действие, ссылки, навигация | кнопки, активная вкладка |
| `success` (зелёный) | сделано, решено, «Вы поддержали», «Вы идёте» | статус «Решено», блоки `.voted`/`.joined` |
| `warning` (янтарный) | ждём, нужны голоса, бронь | статус «Собираем голоса», «Забронировано» |
| `secondary` (бирюзовый) | в работе | статус «Чинят», тип «Субботник», документы |
| `tertiary` (фиолетовый) | праздники и соседи | типы «Праздник» и «Для детей», раздел «Соседи» |
| `deep` (красный, заливка) | **только** тревога, просрочка, укрытие, счётчик открытых проблем | `StatusChip` просрочки, экран тревоги |
| `ink` | сильный нейтральный | кнопки поверх фото |

Правила:

- цвет **всегда дублирует** иконку и подпись и никогда не заменяет их (дальтонизм, яркое солнце);
- красный - экономно: Кузя сам одет в красное, заливка красным только у тревоги и просрочки;
- тёмная тема - нейтральный графит, а не ультрамарин; тревога и там красная заливка с белым текстом;
- фон светлой темы серо-белый (`#F5F7FA`), карточки белые с тонкой границей и мягкой тенью;
- аватары соседей - шесть спокойных цветов (`UserAvatar`), чтобы людей можно было различать;
- типы событий не берут `success` и `warning`: зелёный субботник читался как «уже прошло», янтарный - как «ждём»;
- цены, числа, названия - нейтральным текстом; синий только у того, что нажимается.

Цвета берутся только из токенов темы: `rgb(var(--v-theme-*))` в CSS, `color="primary|success|..."`
в Vuetify, `text-primary`/`bg-surface` в Tailwind. Никаких hex в компонентах.

Контраст текста не ниже WCAG AA (4.5:1 для обычного, 3:1 для крупного). Проверяется `__ui.audit()`.

## Сетка и отступы

- Шаг 4px. Типовые значения: 8 (между элементами), 12 (между карточками), 16 (поля экрана, внутри карточки), 24 (между секциями).
- Контент - колонка до 640px (`--app-max-width`), поля 16px.
- Нижнее меню видно только на пяти корневых вкладках; на внутренних экранах (`meta.inner`) оно прячется, назад ведёт кнопка «Назад» и системная кнопка MAX.
- Внизу экрана место под навигацию: `--nav-space` = высота капсулы + отступ от края + safe-area. `.page`, `.fab`, `.sticky-cta` и тосты уже его учитывают; своё фиксированное снизу считаем тоже от `--nav-space`.
- Карточка: `.card-soft` (радиус 28px, мягкая тень). Нажимаемая карточка: + `.tap-card`.

### Форма в духе iOS 26

- Скругления только из шкалы `main.css`: `--r-sm` 14px (плитки, мелкие блоки), `--r-md` 18px (поля, блоки внутри карточки), `--r-lg` 24px (меню), `--radius-card` 28px (карточки). Внутренний элемент скругляем меньше внешнего на величину отступа, чтобы углы шли концентрично.
- Кнопки и чипы - капсулы (`rounded: 'pill'` по умолчанию в `vuetify.ts`). Нижний лист `Drawer` - 32px сверху.
- Поля ввода - плашки без рамки (`solo-filled`) на заливке плотнее iOS-плашки, чтобы поле читалось на белой карточке; в фокусе синее кольцо 2px.
- Стекло (`.glass`, полупрозрачный фон с размытием) только на навигации, шапке и всплывающих меню. Контент всегда на непрозрачной карточке. При «Уменьшить прозрачность» и без поддержки `backdrop-filter` стекло становится сплошной поверхностью.
- Нижняя навигация - плавающая капсула с отступом от краёв; активная вкладка - подложка-«линза» под иконкой и подписью. Подписи вкладок не убираем.
- Однотипные строки (соседи, документы, разделы) - сгруппированный список `.group-list` со строками `.tap-row`: одна карточка, разделители с отступом `--group-inset` от иконки, нажатие подсвечивает строку.
- Переключатель видов списка - `SegmentedControl` (капсула с «бегунком»), а не `v-tabs` и не `v-btn-toggle`.
- Нажатие: карточки сжимаются до 0.97 с пружинным возвратом (`--ease-spring`), строки списка подсвечиваются фоном.

## Компоненты: что брать

Основа - **Vuetify** (кнопки, поля, чипы, табы, списки, диалоги). shadcn-vue используется точечно:
`Drawer` (нижний лист), `Skeleton`, `Sonner` (тосты). Новые примитивы берём из Vuetify;
shadcn - только если в Vuetify нет аналога. Не смешивать две реализации одного элемента.

|---|---|
| Главное действие экрана | `v-btn size="x-large" block color="primary"`; в формах + `.sticky-cta` |
| Создать новое из списка | `AppFab` справа над навигацией, с подписью; при прокрутке вниз сворачивается в круг с «+» |
| Второстепенное действие | `v-btn variant="tonal"` или `variant="text"` |
| Статус | `StatusChip` (иконка + подпись) |

| Срок | блок `.sla` с таймером `useCountdown` |
| Подтверждение / ввод к действию | нижний лист `Drawer`, не модальное окно по центру |
| Загрузка списка | `ListSkeleton`; повторная загрузка - тонкая полоса `v-progress-linear` |
| Пусто / ошибка | `EmptyState` / `ErrorState` с кнопкой следующего шага |
| Короткое подтверждение | `notify.success(...)` (тост) + `haptic` |
| Сделанный выбор («Вы поддержали», «Вы идёте») | общий зелёный блок-состояние `.voted`/`.joined` из `main.css` (не кнопка) + отдельная `variant="text"` кнопка отмены |
| Плавающая кнопка «создать» | `AppFab` из `components/common`: рисуется в слое `#fab-layer` вне анимируемой страницы, поэтому стоит на месте с первого кадра. У страницы `.page--with-fab` (список не прячется под кнопкой); пока список пуст, кнопку не показываем - действие в `EmptyState` |
| Необратимое действие (удалить) | нижний лист `Drawer` с вопросом, красная кнопка `color="deep"` и «Оставить» |
| Название организации | `orgTitle()`/`orgTitleCap()` из `utils/format`: «УК» → «управляющая компания», «Регоператор ТКО» → «оператор вывоза мусора». После предлога - `orgRecipient()` («в управляющую компанию …», «оператору вывоза мусора …»), в винительном - `orgAccusative()`; в свободном тексте (ход заявки) - `plainOrgWords()`. Никогда «в {{ orgTitle }}» |
| Действие в каждой карточке списка («Иду») | `variant="outlined"` `color="primary"`: заливная кнопка на экране одна |
| Фильтр-чип | `v-chip size="large" class="filter-chip" role="button" :aria-pressed` (44px) |
| Цифра на вкладке | только то, что ждёт действия жителя (у «Заявок» - заявки без его голоса), цвет `primary`. Цифра уходит, когда житель сделал дело; на экране вкладки строка объясняет, откуда она, и открывает эти записи. Общие счётчики дома на вкладки не вешаем |
| Переключатель видов списка | `SegmentedControl` из `components/common`; свайп пальцем по экрану под ним листает соседнюю вкладку (`useSwipeTabs`) |
| Несколько фото | `PhotoCarousel`: кадр во всю ширину, свайп и перетаскивание мышью, точки снизу; битое фото пропускается, без фото - иконка категории |
| Однотипные строки | `.group-list` + `.tap-row` |
| Просрочка | блок `.overdue` (заливной `deep`) + кнопка следующего шага (жалоба) |
| Маршрут до укрытия | линия `primary` на карте `ShelterMap` (пунктир, если роутер не ответил и маршрут проведён по прямой) + строка «≈ 7 мин пешком · 540 м» (`formatWalk`) под выбранной карточкой. Единственное место с hex-цветами: это скин чужого интерфейса, переменные `--mx-*` в самом компоненте, с тёмным вариантом. ## Паттерны, выведенные из проверок

- **Состояние и действие - разные элементы.** Повторное нажатие на ту же кнопку не должно отменять
  сделанное: житель жмёт второй раз, «чтобы точно сработало».
- **Если нашлось похожее - главное действие «поддержать», а не «создать».** «Дальше» ждёт проверку
  на похожие (до 3 с, «Кузя ищет похожие...») и при находке открывает нижний лист с «Поддержать эту
  заявку» и текстовой «Нет, у меня другая проблема». Блок не появляется посреди формы и не сдвигает кнопки.
- **Ничего не теряется молча.** Поле, которое житель заполнил и ушёл «Назад», сохраняется само
  (номер квартиры в профиле) или защищено `useDirtyGuard`.
- **Кнопки не прыгают под пальцем.** Подсказки, которые появляются во время ввода, получают место
  заранее (`min-h`), скрытая подсказка остаётся в потоке (`invisible`), а не исчезает.
- **Нажатие отвечает сразу.** Если действие ждёт сеть, загрузка на кнопке с первого кадра.
- **Последний шаг обучалки** - главная кнопка на месте «Дальше» просто закрывает обучалку
  («Понятно, начать»): нажатие в ритме не уводит в форму. Дело («Сообщить о проблеме») -
  второстепенной кнопкой. У админа главная - «Настроить дом», об этом сам шаг.
- **Главное действие - на первом экране 375×812** без прокрутки. Игровые блоки (уровни, очки) ниже.
- **Статусы заявок** - только из `ISSUE_STATUS_TITLES` («Собираем голоса», «Чинят»...), а не `status_title` сервера.
- **Сроки** - `formatHours()`: до 48 часов часами, дальше днями.
- **Фраза Кузи ведёт туда, о чём он говорит** (просрочка, тревога) - ссылка под пузырём.
- **Экран тревоги** - `alertdialog` с фокусом на себе, остальное приложение `inert`.
- Подписи нижней навигации - одно короткое слово (пятая часть экрана 360px).

## Состояния, которые обязан иметь каждый экран со списком или данными

1. загрузка (скелетон), 2. пусто (с действием), 3. ошибка (с «Попробовать ещё раз»),
4. обычное, 5. длинные тексты и имена (ничего не вылезает и не обрезается без многоточия),
6. тёмная тема. Для проверки есть сценарии мок-режима (ниже).

## Тексты

- Кнопки - глагол или фраза от лица жителя: «Сообщить о проблеме», «Иду», «Меня это тоже касается».
- Числа с правильным склонением через `plural()`/`pluralize()` из `utils/format`.
- Без канцелярита и аббревиатур без расшифровки при первом упоминании (ГЖИ → Госжилинспекция).
- Тире в тексте интерфейса - обычный дефис с пробелами или перестройка фразы.

## Движение

GSAP через `composables/useMotion`. Любая анимация обязана уважать `prefersReducedMotion()`
и не блокировать интерфейс: переход экрана не ждёт кадров, если движение выключено.

Кузя (`KuzyaMascot`) двигается медленно и мягко, иначе читается как дёрганье: циклы дыхания и
покачивания головы не короче 2,4 с, амплитуда поворота до 2°, синусоидальная кривая без ускорений
на концах хода, без вертикальных подскоков в цикле. Смена позы - перекрёстное растворение 0,26 с,
прыжок по нажатию - одна дуга с мягким приземлением (`back.out`), моргание 0,1-0,16 с. Пульс экрана
тревоги - 1,6 с в одну сторону.

# Цикл проверки (обязателен после любой правки UI)

1. Запустить мок: `npm run dev:mock`, порт 5174.
   Мок не ходит в бэкенд и не пишет в домовой чат.
2. Для каждого изменённого экрана снять скриншоты в мобильном размере (375×812) в светлой и тёмной теме
   (`?theme=dark`). Чтобы увидеть экран целиком,
   можно временно задать высоту 1400-1600.
3. Прогнать в консоли страницы `await __ui.audit()` - тач-зоны, мелкий текст, горизонтальный скролл,
   обрезка текста, axe (WCAG AA). Новых нарушений быть не должно.
4. Проверить затронутые состояния через сценарии: `?scenario=empty|overdue|alert|long|error`, `?latency=2000`.
5. Сверить экраны с принципами и паттернами выше и пройти ключевые сценарии глазами жителя 60+.
   Исправить всё с приоритетом P0-P1 и повторить проверку.
6. `npm run typecheck && npm run lint && npm test`.

## Параметры мок-режима

| Параметр | Значения | Зачем |
|---|---|---|
| `scenario` | `default`, `empty`, `overdue`, `alert`, `long`, `error`, `boot-error` | состояние данных |
| `role` | `resident`, `admin` | права (кнопки управления статусом) |
| `max` | `0` | браузерный демо-режим с переключателем жителей (по умолчанию имитация MAX) |
| `latency` | мс | увидеть скелетоны и спиннеры |
| `theme` | `dark`, `light`, `system` | тема без смены системной |
| `motion` | `0` | выключить анимации для стабильных скриншотов (по умолчанию включены) |
| `reset` | `1` | забыть сохранённые параметры вкладки |

Параметры запоминаются на вкладку. Данные живут в памяти до перезагрузки: голоса, «Иду», новые заявки работают.
